# TASK-301: 分割スクリーンシステム実装 要件定義書

## 概要

Bird Dive Challengeゲームにおいて、第一人称視点とサイドビュー視点を同時表示する分割スクリーンシステムを実装する。USplitScreenManagerコンポーネントを中心とした2画面レンダリングシステムにより、プレイヤーの飛行体験を向上させる。

## ユーザストーリー

### ストーリー1: 2画面同時表示による飛行体験向上

- **である** プレイヤー **として**
- **私は** 第一人称視点とサイドビュー視点を同時に見ながら鳥を操作したい
- **そうすることで** より没入感のある飛行体験と正確な位置把握ができる

### ストーリー2: 動的な画面分割比率調整

- **である** プレイヤー **として**
- **私は** 2つのビューポートの表示比率をリアルタイムで調整したい
- **そうすることで** 自分の好みに合わせた視点配分で快適にプレイできる

### ストーリー3: 複数の分割方向対応

- **である** プレイヤー **として**
- **私は** 水平分割（上下）と垂直分割（左右）を選択したい
- **そうすることで** 画面サイズや個人の好みに最適な分割方向でプレイできる

### ストーリー4: 高品質な2画面レンダリング

- **である** プレイヤー **として**
- **私は** 両方のビューポートで高品質な映像を同時に見たい
- **そうすることで** 視覚的に満足できるゲーム体験を得られる

## 機能要件（EARS記法）

### 通常要件（SHALL）

- **REQ-301-001**: システムは2つの独立したビューポートを同時にレンダリングしなければならない
- **REQ-301-002**: システムはUSplitScreenManagerコンポーネントを提供しなければならない
- **REQ-301-003**: システムは各ビューポートに独立したカメラを割り当てられなければならない
- **REQ-301-004**: システムは水平分割（上下）と垂直分割（左右）の両方をサポートしなければならない
- **REQ-301-005**: システムは分割比率を0.2から0.8の範囲で設定できなければならない
- **REQ-301-006**: システムは各ビューポートの適切なアスペクト比を計算・維持しなければならない
- **REQ-301-007**: システムはレンダーターゲットを効率的に管理しなければならない
- **REQ-301-008**: システムはGameModeまたはPlayerControllerに統合できなければならない

### 条件付き要件（WHEN/IF-THEN）

- **REQ-301-101**: 分割比率が変更された場合、システムは新しい比率で即座にビューポートを再配置しなければならない
- **REQ-301-102**: 分割タイプが変更された場合、システムは新しいレイアウトで即座に画面を再構成しなければならない
- **REQ-301-103**: カメラが削除された場合、システムはそのビューポートを無効化し、エラーを発生させてはならない
- **REQ-301-104**: 画面解像度が変更された場合、システムは新しい解像度に合わせてビューポートサイズを再計算しなければならない
- **REQ-301-105**: 無効なカメラが割り当てられた場合、システムは警告ログを出力し、デフォルトカメラを使用しなければならない
- **REQ-301-106**: レンダーターゲット作成に失敗した場合、システムはグレースフルに処理を継続しなければならない

### 状態要件（WHERE）

- **REQ-301-201**: ゲーム実行中にある場合、システムはリアルタイムで分割比率を変更できなければならない
- **REQ-301-202**: 初期化状態にある場合、システムはデフォルト設定（水平分割、50:50比率）で開始しなければならない
- **REQ-301-203**: 終了処理中にある場合、システムは全てのレンダーターゲットとリソースを適切に解放しなければならない

### オプション要件（MAY）

- **REQ-301-301**: システムは分割境界線を表示してもよい
- **REQ-301-302**: システムは分割比率変更時にアニメーション効果を適用してもよい
- **REQ-301-303**: システムはデバッグ情報を表示してもよい

### 制約要件（MUST）

- **REQ-301-401**: システムはメインスレッドでのみレンダリング処理を実行しなければならない
- **REQ-301-402**: システムは最大2つのビューポートまでしかサポートしてはならない
- **REQ-301-403**: システムは分割比率を20:80から80:20の範囲に制限しなければならない
- **REQ-301-404**: システムはUnreal Engine 5.6のレンダリングパイプラインと互換性を保たなければならない

## 非機能要件

### パフォーマンス（Performance）

- **NFR-301-001**: システムは60FPS@1080pで安定動作しなければならない
- **NFR-301-002**: システムはGPU使用率を70%以下に維持しなければならない
- **NFR-301-003**: システムはシングルスクリーンレンダリングの1.6倍以下のレンダリング負荷でなければならない
- **NFR-301-004**: システムは分割比率変更の応答時間を100ms以下にしなければならない

### メモリ使用量（Memory）

- **NFR-301-101**: システムは追加のレンダーターゲット用メモリを効率的に管理しなければならない
- **NFR-301-102**: システムはメモリリークを発生させてはならない
- **NFR-301-103**: システムは1920x1080解像度でレンダーターゲット用に最大200MBのメモリを使用してもよい

### 信頼性（Reliability）

- **NFR-301-201**: システムは24時間連続動作でもクラッシュしてはならない
- **NFR-301-202**: システムはカメラ削除やレンダーターゲット作成失敗などの異常状況から自動復旧しなければならない
- **NFR-301-203**: システムは不正な分割比率値に対して適切に処理しなければならない

### ユーザビリティ（Usability）

- **NFR-301-301**: システムは直感的なBlueprint統合インターフェースを提供しなければならない
- **NFR-301-302**: システムは分割比率変更を滑らかに実行しなければならない
- **NFR-301-303**: システムは設定変更の効果を即座にプレビュー表示しなければならない

### 互換性（Compatibility）

- **NFR-301-401**: システムはNVIDIA RTX系およびAMD RX系GPUで動作しなければならない
- **NFR-301-402**: システムは1920x1080、2560x1440、3840x2160解像度をサポートしなければならない
- **NFR-301-403**: システムはWindows 11環境で動作しなければならない

## Edgeケース

### エラー処理（Error Handling）

- **EDGE-301-001**: カメラが削除された場合、システムは代替処理を行い、プレイ継続可能な状態を維持する
- **EDGE-301-002**: レンダーターゲット作成に失敗した場合、システムは低解像度での作成を試行する
- **EDGE-301-003**: GPU メモリ不足の場合、システムは片方のビューポートを無効化して動作を継続する
- **EDGE-301-004**: 無効な分割比率が設定された場合、システムは最も近い有効値にクランプする

### 境界値（Boundary Values）

- **EDGE-301-101**: 分割比率が0.2未満または0.8超過の場合、自動的に有効範囲内にクランプする
- **EDGE-301-102**: 画面解像度が極小（100x100未満）の場合、最小サイズ制限を適用する
- **EDGE-301-103**: 画面解像度が極大（8K超過）の場合、レンダーターゲット解像度を制限する

### リソース不足（Resource Constraints）

- **EDGE-301-201**: メモリ不足時は単一ビューポートモードに自動切り替え
- **EDGE-301-202**: GPU負荷過大時はレンダリング品質を動的に調整
- **EDGE-301-203**: フレームレート低下時は一時的に片方のビューポート更新を停止

### 同期問題（Synchronization Issues）

- **EDGE-301-301**: 複数スレッドからの同時アクセス時はメインスレッドでの実行を強制
- **EDGE-301-302**: レンダーターゲットの更新タイミングずれ時は次フレームで同期修正

## 技術仕様

### アーキテクチャ要件

```cpp
// Core Component Architecture
UCLASS(BlueprintType, Blueprintable, Category = "Camera")
class BIRDDIVE_API USplitScreenManager : public UActorComponent
{
    GENERATED_BODY()

public:
    // Configuration Properties
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Split Screen")
    ESplitScreenType SplitType = ESplitScreenType::Horizontal;
    
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Split Screen", 
              meta = (ClampMin = "0.2", ClampMax = "0.8"))
    float SplitRatio = 0.5f;
    
    // Core Methods
    UFUNCTION(BlueprintCallable, Category = "Split Screen")
    bool InitializeSplitScreen();
    
    UFUNCTION(BlueprintCallable, Category = "Split Screen")
    bool SetSplitRatio(float NewRatio);
    
    UFUNCTION(BlueprintCallable, Category = "Split Screen")
    void SetSplitType(ESplitScreenType NewType);
    
    UFUNCTION(BlueprintCallable, Category = "Split Screen")
    bool AssignCamera(int32 ViewportIndex, ACameraActor* Camera);

protected:
    TArray<FViewportInfo> Viewports;
    TArray<ACameraActor*> AssignedCameras;
    TArray<UTextureRenderTarget2D*> RenderTargets;
};
```

```cpp
USTRUCT(BlueprintType)
struct FViewportInfo

    GENERATED_BODY()

    UPROPERTY(BlueprintReadOnly)
    UTextureRenderTarget2D* RenderTarget;

enum class ESplitScreenType : uint8

    Vertical    UMETA(DisplayName = "Vertical (Left/Right)")
```

## リスク分析

### 高リスク
- **パフォーマンス低下**: 2画面レンダリングによるGPU負荷増大
- **メモリ使用量増加**: レンダーターゲット分の追加メモリ消費

### 中リスク  
- **レンダリング同期**: 2つのビューポート間の同期問題
- **カメラ管理**: 動的なカメラ割り当ての複雑性

### 低リスク
- **UI統合**: Blueprint統合の学習コスト
- **設定永続化**: 分割設定の保存・復元
